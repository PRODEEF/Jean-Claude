# 200 — Application Expo (`apps/app`)

Un seul codebase produit le web, iOS et Android. Le desktop sera un wrapper
autour du build web.

## Structure

```
src/
  app/          Routes Expo Router (file-based)
    (auth)/     Parcours de connexion
    (app)/      Application authentifiée, navigation par onglets
  features/     Une feature métier par dossier
  shared/       Ce qui sert à plusieurs features
    ui/         Composants génériques
    hooks/      Hooks transverses
    lib/        env, supabase, api, token-storage
    providers/  Contextes React
```

Détail : skill [app-feature](../skills/app-feature/SKILL.md).

## Règles multi-plateforme

**Divergence par taille d'écran → `useBreakpoint()`.**

```ts
const breakpoint = useBreakpoint(); // "compact" (< 768pt) | "expanded"
```

`compact` → onglets et tiroir. `expanded` → sidebar permanente, comme la
maquette web.

**Divergence franche par plateforme → extensions de fichier.**
`Composant.web.tsx` / `Composant.native.tsx`. Metro choisit automatiquement.
À réserver aux cas où le composant est réellement différent — pas pour un
écart de padding.

**Ne jamais tester `Platform.OS` pour décider d'une taille.** Un navigateur en
fenêtre étroite doit se comporter comme un téléphone.

## Composants

**Ne jamais réécrire un composant qui existe déjà.** Chercher dans cet ordre,
et n'écrire de zéro que si les trois échouent :

1. `shared/ui/` — ce que le dépôt porte déjà
2. **[react-native-reusables](https://reactnativereusables.com)** — le portage
   de shadcn/ui pour React Native. Même modèle : la CLI copie le composant
   **dans le dépôt**, il devient éditable, il n'y a pas de dépendance opaque
3. Une primitive React Native (`Pressable`, `FlatList`, `Modal`)

```bash
npx @react-native-reusables/cli@latest add button
```

❌ **shadcn/ui lui-même est inutilisable ici.** Radix et Tailwind sont du React
DOM : ils ne tournent ni sur iOS ni sur Android. Un seul codebase sert les
quatre plateformes, un composant web-only y ferait diverger le rendu mobile.

> NativeWind 4 est installé dans `apps/app`. Son articulation avec `@jc/design`
> est tranchée : **la palette de `useTheme()` reste la seule source des
> couleurs**. `ThemeProvider` la publie en variables CSS (`vars()` de
> NativeWind) et `tailwind.config.js` ne fait que pointer vers ces variables —
> aucune couleur n'y est écrite en dur. Conséquence : la couleur d'assistant
> choisie par l'utilisateur (§5.1) se propage aux classes utilitaires comme
> aux `StyleSheet` existants.
>
> Les jetons portent les noms de shadcn (`primary`, `muted`, `card`…), sans
> quoi les composants copiés depuis react-native-reusables s'afficheraient
> sans style. Attention au faux ami : le `accent` de `@jc/design` est la
> couleur de marque et devient `primary` ; le `accent` de shadcn est le fond
> de survol.
>
> Les composants déjà copiés dans `shared/ui/` : `avatar`, `button`,
> `collapsible`, `icon`, `separator`, `text`. Le bloc `sidebar` de shadcn
> n'existe pas côté react-native-reusables (il tient à Radix) — il est
> recomposé dans `features/navigation/AppSidebar.tsx`.

## Style

- Couleurs : toujours `useTheme().palette`, jamais de valeur en dur
- Espacements, rayons, tailles : jetons de `@jc/design`
- Toute zone cliquable : au moins `MIN_TOUCH_TARGET` (44 pt)
- Borner la largeur des contenus (`maxWidth`) — la même vue sert un téléphone
  et un écran desktop
- Tester le thème clair **et** le thème sombre

## Données

**L'app n'écrit jamais en base directement.** Supabase côté client sert
uniquement à l'authentification. Tout le reste passe par `@jc/api-client`.

**Les appels serveur passent par React Query**, jamais par un `useEffect` +
`useState` manuel.

```ts
const { data, isLoading, error } = useQuery({
  queryKey: ["conversations"],
  queryFn: () => api.conversations.list({ limit: 30 }),
});
```

Clés de cache : tableau descriptif, du plus général au plus spécifique —
`["conversations"]`, `["conversation", id]`, `["conversation", id, "messages"]`.

## Accessibilité

- `accessibilityRole` sur tout élément interactif
- `accessibilityLabel` dès que le libellé visible ne suffit pas
- Les champs de saisie : `autoComplete`, `textContentType`, `keyboardType`
  corrects — c'est ce qui active le remplissage automatique du code OTP

## Interdits

- ❌ Pas de logique métier dans un écran → elle vit dans l'API ou `@jc/domain`
- ❌ Pas de secret : `EXPO_PUBLIC_*` finit dans le bundle
- ❌ Pas d'appel `fetch` direct → passer par `@jc/api-client`
